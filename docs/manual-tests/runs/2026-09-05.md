### 9. Timezone / hydration (`0696d74`, `b450e1b`) — mostly verified already

✅ **Verified off-device, no iPhone needed.** `appTodayKey()` returns the same
value under `TZ=UTC` (what the prod server runs) and `TZ=Europe/Paris` (what a
French browser runs) at every instant tested, including across the day boundary.
The naive version it replaced diverges under UTC exactly in that window:

```
2026-09-05T22:30:00Z   anchored=2026-09-06   naive under TZ=UTC=2026-09-05
2026-01-15T23:30:00Z   anchored=2026-01-16   naive under TZ=UTC=2026-01-15
```

The bug window in Paris local time is **00:00–02:00** (CEST) — i.e. just after
midnight, not late evening. You are not testing at that hour, so these would
have been untestable by hand today regardless.

- [x] Still worth one device check, valid at any hour: Web Inspector console on a
      fresh SSR load of `/church/<uuid>` and `/diocese/paris` — **no hydration
      mismatch warnings**.
- [x] Sanity only: the date rail's first chip reads "Aujourd'hui" and matches today.
